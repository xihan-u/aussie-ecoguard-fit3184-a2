# Inert member-C controller: V13 lifecycle and Head JSON fix

This is a reviewable **inert code snapshot**, not a deployment or a cloud entry
point. It preserves the V13 lifecycle and changes only the driver fixture-module hash
pin for the reviewed Head JSON fix. `ARM_REVIEWED = False`, preparer pin `None`
and all60 actual pins remain pending. The ARMTrue RELEASE file, consumed
bindings/approvals, credentials, private logs, saved plans and Terraform state
are deliberately absent. No existing approval can be replayed from this tree.

V13 starts durable writer heartbeats before watchdog startup and uses a readiness
bound within the original 600-second window, capped by the existing stop reserve.
It does not weaken fixture, funding, identity, boundary, once-only or drain gates.
These changes passed nine deterministic injected-stub tests and independent
static review in the original work snapshot. This does not prove native Linux
scheduling, CloudShell SDK startup, real IAM/WIF, model processing, or recovery
under active work. All three attempts remain failed media tests. Attempt3 verified activation and
initial pause within600 seconds, but stopped before seed/PUT and failed its
continuous observation tail. The new Head fix has not been deployed or cloud-tested.

## Run only the offline tests

From the repository root, using Python 3.10 or newer and the standard library:

```sh
python3 -B -m unittest discover -s tools/c-runtime-controller/tests -v
```

Or from this directory:

```sh
python3 -B -m unittest discover -s tests -v
```

The tests inject clock, thread, process, IPC and cloud-port stubs. They start no
real thread or process, invoke no signal/CLI/SDK, and contact no cloud service.
The suite contains nine lifecycle tests and eight Head JSON fixture tests. The
latter include strict404 parsing,403/auth/malformed/duplicate/oversized rejection,
unchanged successful metadata, conditional seed/PUT, once-only and identity/STOP
checks. They use temporary **synthetic bytes**, not a real image payload.

`tests/fixtures/cli2381-head-error-examples.json` contains explicitly synthetic
errors generated by the original pinned2.38.1 formatter AST in a separate local
proof. It links the exact official source; the work proof and large AWS sources
are not bundled. These examples do not establish the historical failed stderr.
The V12 static baseline retains its original hashes and adds portable structural
AST fingerprints: only optional empty fields are omitted across Python versions;
all real syntax and literal values remain checked. The reviewed fixture hash is
the sole dependency exception. `SNAPSHOT.json` records this packaging and all
source hashes. Local tests are not a runtime approval or cloud acceptance.

## Deliberately incomplete runtime binding

The unchanged driver contains exact historical Linux CloudShell paths and hash
pins. The current VM, CLI/SDK package inventory, source tree, native plans,
funding, fixture IDs, fresh GCP metadata and human authority are **not completely
bound** here. The referenced private artifacts and executable release are not
included. Do not run this snapshot against cloud resources, set ARMTrue, replace
pins, or treat a passing local test as permission to activate an application.

All other production candidate modules and the pending-binding template remain
byte-for-byte V13 copies. Only `fixture_runtime.py` and its inert driver hash pin
change: HeadObject requests explicitly use JSON error formatting, and absence
requires exit254, empty stdout and exactly Code404/MessageNot Found. Errors keep
safe diagnostic categories and output lengths/hashes without raw error or
credential bodies. Positive200 handling and non-Head call arguments remain
unchanged. Both pre-upload and post-production source absence use this path. `reference/automatic_fixture_DRAFT.py` is the fixed inert
fixture helper for source review; its relocated reference path intentionally
does not satisfy the driver's original runtime path. Source Terraform gate files
remain in `infra/aws/environments/personal`; their historical pins do not assert
fresh deployment acceptance. No product implementation or Terraform is changed
by this snapshot.

See [actual attempts and recovery](../../docs/c-runtime-attempt-and-recovery-20261025.md)
for current operational limits. Real image/WIF success remains zero at this
checkpoint; continuous paused controls/funding do not establish fixture drain.
